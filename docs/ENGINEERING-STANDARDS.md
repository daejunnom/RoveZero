# RoveZero 개발·검증 기준

이 문서는 신규·변경 코드와 연구 자료의 품질 기준입니다. 에이전트 진입점은
[AGENTS.md](../AGENTS.md), 협업 절차는 [CONTRIBUTING.md](../CONTRIBUTING.md)입니다.
프로젝트 책임은 [아키텍처](ARCHITECTURE.md), 대국·통계 조건은 [실험 계약](EXPERIMENTS.md),
채택·보류·미결정은 [결정 기록](DECISIONS.md)에 둡니다. 사용자 직접 지시가 우선합니다.
문서는 기본적으로 한국어로 작성하고 같은 규칙의 복제 문서를 늘리지 않습니다.
실제 구현 작업·의존성·단계 인수는 [구현 지시서](IMPLEMENTATION-DIRECTIVES.md),
상태·평가·요청 수명의 상세 타입은 [공통 계약](CONTRACTS.md)이 주 기준입니다.

## 적용 강도와 결정 상태

표준 체스 규칙과 정확한 상태를 보존하고 근사화는 특징·평가·탐색 실험에서 명시합니다.
규칙·타입 경계·캐시·비동기 결과·학습 데이터는 오류가 후속 계산에 전파되는 영역이므로
입력·실패·소유권·버전·재현 근거를 엄격히 다룹니다. 연구 구조와 파라미터 실험은 허용하되
출처의 성능 보고, 하드웨어 적합성 추론, 자체 측정과 채택·승격을 구분합니다.

[핸드오프 원문](reference/README.md)의 ‘확정’, ‘권고’, ‘가설’, ‘미확정’을 유지하고
최신 사용자 지시와 구별합니다. 확정한 구현 기반은 **독립 Rust workspace·자체 MIT 코드·
자체 체스 코어·최소 PUCT 기준선**입니다. LC0 fork나 외부 UCI 프로세스를 내부
신경망 API로 삼는 구현은 아닙니다. 외부 코드·가중치·데이터·opening의 권리는 각각
확인하며 자체 코드의 MIT 라이선스로 묶지 않습니다.

첫 weights는 [선정 기록](WEIGHT-SELECTION.md)의 Maia1 v1.0 한 종류입니다.
권리·파일 형식 조사와 실제 목표 GPU 인수를 구분합니다. 실제 backend·학습 도구 언어·
최종 모델 파라미터·학습/GPU 예산과 LC0 기준선·
대국 조건은 [결정 기록](DECISIONS.md)과 실행 manifest로 잠급니다. ONNX·FiLM·
LoRA·recurrent·warm-start를 미확정 상태에서 필수 구현으로 고정하지 않습니다.
문서 채택은 Cargo 생성·구현·실행 완료가 아닙니다.

## 총괄·공통 계약·병렬 작업

총괄로 배정된 에이전트가 TASK-I01/I02와 최소 공통 계약을 직접 소유합니다.
각 담당은 사용자 배정에서 자신의 총괄 또는 A~F 역할·TASK ID·소유 경로를 확인합니다.
`crates/rz-contracts/`의 선언·revision·오류·식별·수명 계약은 총괄이 게시·변경합니다.
TASK-A03은 position과 요청·응답 계약의 적용·검증을 맡으며 공통 선언을 별도로
정의하지 않습니다. 각 담당은 변경 제안의 이유·영향 consumer·호환성과 인수 벡터를
총괄에 전달하고 갱신한 동일 revision을 사용합니다.

총괄의 최초 계약 게시 뒤 A·B·C01·D01·E·F01은 mock·fixture로 병렬 개발합니다.
다른 담당의 전체 기능 완성을 기다리는 의존성을 만들지 않으며 shared 인터페이스는
WIP 단계부터 공유합니다. 총괄은 실제 선행 계약·실행 근거가 필요한 인수 단계에서
소비자 검사·독립 리뷰·실패와 미검증 범위를 확인합니다. 담당자 자체 완료 선언과
총괄 통합 인수, 연구 후보의 강도 승격은 서로 다릅니다.

A~F의 클라우드 개발 환경에는 GPU가 없을 수 있습니다. CPU/mock 기본 조합과
가능한 CPU 신경망 참조를 별도 지정한 실제 GPU 검증 환경과 구분합니다.
CUDA capability 부재는 환경 상태로 기록하고 GPU 모드를 조용히 CPU로 대체하지
않습니다. GPU backend 코드·fixture·검사 진입점과 학습 recipe·resume 검사는
지원하는 CPU/mock 범위에서 먼저 구현할 수 있습니다. CPU/mock CI 통과와 GPU
검사의 skip·미실행은 별도 결과입니다. 총괄 I02가 지원 환경의 실제 GPU·arena·학습
근거를 따로 인수합니다. D02 CPU 지연은 GPU 계측이 아니며 D03 GPU 성능 개선은
실제 목표 환경 측정 후 주장합니다. 코드 인수와 실제 학습·정식 강도 인수를 혼동하지 않습니다.

초기 RTX 4050 검증은 해당 장비의 이력입니다. 후속 GPU 벤치마크는 사용자 지정
외부 RunPod 환경에서 준비하며 [준비 계획](research/RUNPOD-BENCHMARK-PLAN.md)의
새 host·image·GPU·driver·자원 통제·비용·산출물 회수 조건을 실제 실행 전에 잠급니다.
GPU A/B 전에 [의미 보존 최적화](research/PRE-RUNPOD-OPTIMIZATION.md)의 CPU 검증을
먼저 인수합니다. Community/no network volume·초기 총예산·외부 회수의 현재 결정과
하위 실행 한도는 준비 계획을 따르며 CPU 감소율을 GPU 종단 개선으로 바꾸지 않습니다.
다른 GPU의 용량을 6GB로 제한한 결과를 RTX 4050 성능으로 표시하지 않습니다.

## Power of Ten 조정표

NASA/JPL의 신뢰성 원칙을 프로젝트에 맞게 조정합니다. NASA 분류·인증·전면 준수를
주장하지 않습니다. 실제 Rust toolchain·feature·실행 경로가 도입될 때 관련
compiler/lint/type 검사의 명령·범위를 설정합니다.

| 원칙 | RoveZero 적용과 검증 |
|---|---|
| 단순 제어 흐름·재귀 제한 | 상태 전이를 명시합니다. 탐색 재귀는 깊이·노드·시간 한도로 제한하고 한도 도달을 확인합니다. |
| 반복 횟수 상한 | 유한 입력 순회, game/step/time·retry 한도와 취소 경로를 둡니다. 상한 없는 재시도를 금지합니다. |
| 동적 할당 제한 | 할당을 허용하되 buffer·batch·queue·cache 크기와 소유권, 자원 부족 오류를 검사합니다. |
| 작은 함수 | 하나의 변경 이유와 검토 가능한 인터페이스를 기준으로 합니다. 고정 줄 수로 함수·파일을 분할하지 않습니다. |
| assertion | 실제 전후 조건·불변식·경계 오류를 확인합니다. 개수 할당·항상 참인 assertion을 추가하지 않습니다. |
| 최소 변수 범위 | 전역 가변 상태를 줄이고 게임·RNG·모델·캐시·작업의 소유자와 수명을 명시합니다. |
| 입력·반환값 검사 | 외부 입력과 실패를 검증·전파합니다. 예상 가능한 입력 실패를 무조건 panic·성공 기본값으로 바꾸지 않습니다. |
| 전처리기·코드 생성 제한 | 표준 매크로와 필요한 feature/cfg를 허용하되 지원 조합과 생성 책임을 명시합니다. |
| 포인터·unsafe 제한 | 작은 FFI·native 경계로 제한하고 수명·소유권·동시성·오류 처리 근거를 남깁니다. |
| 경고·정적 분석 | 변경 영역의 compiler/lint/type 검사를 수행합니다. 새 경고는 수정하거나 좁은 범위의 근거를 남깁니다. |

규약 예외는 규칙·이유·보완 검사·재검토 조건을 PR에 기록합니다. 정당한 예외를 이유로
일상적인 구현 선택마다 별도 승인 절차를 만들지 않습니다.

## 책임 구성과 검사 유지비

SRP는 기능·변경 이유·소유권·인터페이스 기준입니다. 관련 구현과 보조 코드는 함께 두고
독립 책임·재사용 경계가 생기면 분리합니다. 작은 함수별 파일, 책임 없는 `utils`·`common`,
실험별 운영 복제판과 미래용 빈 폴더를 늘리지 않습니다. 사용자가 정한 책임 경로는
다음과 같으며 상세 의존 방향은 [구현 지시서](IMPLEMENTATION-DIRECTIVES.md)를 따릅니다.
문서 정비만 배정된 작업에서 빈 crate나 소스 폴더를 생성하지 않습니다.
실제 구현이 배정되면 필요한 책임 경로를 만들고 소유·의존 방향을 검증합니다.

| 소유자 | 구현 경로·책임 |
|---|---|
| 총괄 | 루트 Cargo·공통 설정·CI·`crates/rz-contracts/`의 최소 계약과 통합 인수 |
| A | `crates/rz-position/`의 자체 규칙·정확한 상태·이력·종료와 계약 적용 |
| B | `crates/rz-search/`, `crates/rz-uci/`의 최소 PUCT·새 search·UCI·착수/취소 |
| C | `crates/rz-encoding/`, `crates/rz-eval/`의 단일 weights 인코딩·실제 NN 추론 |
| D | `crates/rz-runtime/`, `crates/rz-telemetry/`, `benches/runtime/`의 큐·수명·계측·단일 최적화 |
| E | `crates/rz-experiments/`, `crates/rz-arena/`, `experiments/baselines/`의 manifest·pair·결과 |
| F | 데이터/학습 도구와 `experiments/model-research/`; 구체 도구 언어·패키지는 별도 결정 |

신경망 소스는 위 `rz-encoding`·`rz-eval` 책임 경로를 사용합니다.
생성 weights의 `models/`는 저장소 밖 출력·접근 제외 영역입니다. 구체 backend는
search의 내부 의존으로 넣지 않고 evaluator 접점과 UCI/bootstrap에서 연결합니다.

테스트는 반복 가능한 중요한 계약과 실패를 지킬 때 유지합니다. 문구 수정이나 버그 한 건마다
새 회귀 검사·fixture를 자동 의무화하지 않습니다. 영향·재발 가능성·기존 검사 누락·유지비를
보고 기존 검사를 먼저 활용하며 최소 재현 입력과 의미 있는 결과에 집중합니다.

새 fixture는 검증할 계약과 기존 자료로 부족한 이유를 PR에 적습니다. 구현 문장만 복제하는
테스트, 중복 snapshot·긴 대국 로그·전체 데이터셋의 버전별 복사본을 쌓지 않습니다.
일회성 조사 자료는 외부 `reports/`에 보관하고 이후 필요한 최소 입력만 소스 fixture로
채택합니다. 파일·테스트 개수나 소스 길이에 합격 할당량을 두지 않습니다. 기존 유효한 검사를
일괄 제거하지 않으며 관련 코드를 바꿀 때 폐기·중복 검사도 함께 검토합니다.

## 타입과 실행 경계

- 규칙·상태는 `rz-position`이 정확성의 단일 소유자입니다. 제품 규칙은 자체 코어로
  구현하고 외부 참조는 독립 검증에 사용합니다. 합법 수·promotion·castling·en passant·
  claimable/automatic draw와 종료 계약은 [공통 계약](CONTRACTS.md)에 맞춥니다. 보드 배치만 같다는
  이유로 전체 상태나 모델 입력이 같다고 판단하지 않습니다.
- `EvalRequest`/`EvalResult` 같은 평가 경계는 요청·상태 식별, 모델·인코딩 버전, 합법 수
  순서, dtype/shape·정밀도·예산·deadline, policy/WDL·관점·완료 상태·캐시 유래를
  타입 또는 검증 가능한 manifest로 명시합니다. 구체적인 wire 형식은 구현 선택 뒤 정합니다.
- tensor 유한값·범위·mask·batch와 policy/action 정렬을 확인합니다. value/WDL 관점과
  부모→자식 변환을 명시하고 후보 순서·padding 때문에 상태 가치가 달라지지 않게 합니다.
- 정확한 재사용 캐시와 경로 의존 근사 warm-state는 구분합니다. 키·이력·모델/인코딩 버전·
  정밀도·수명·provenance가 맞아야 재사용합니다. 비슷한 board hash를 정확한 동일성으로
  취급하지 않습니다. cache lookup 자체로 방문·backup을 추가하지 않으며 새 유효
  traversal이 cached 평가를 소비한 경우만 탐색 계약대로 한 번 반영합니다.
- 실패한 전이는 원본 상태를 보존합니다. 비동기 요청·취소·늦은 결과는 generation과 현재
  root·모델을 확인하여 이전 작업이 새 상태를 오염시키지 않게 합니다. FFI·worker에서는
  입력 배열과 모델의 수명·소유권·동시성·오류 전파를 확인합니다.
- 테스트 참조판·다른 엔진은 검증 또는 명시적 composite 실험에서 사용합니다. 운영 실패를
  숨기기 위해 타 엔진을 자동 호출하지 않습니다. 같은 자체 모델의 완전 재계산 등 채택한
  복구도 시간·정확성·자원 계약과 실제 결과를 확인합니다.

## 경고와 오류 전달

경고·오류를 빈 결과·0 점수·무승부·일반 성공 메시지로 바꾸지 않습니다. 개발 CLI·API·
테스트·CI에 실제 유형·코드·메시지·발생 단계·저장소 상대 위치·원인 chain·exit code·
signal·상태를 전달합니다. 원인이 미확인이라면 관측 진단과 추측을 분리하고 원본에 없는
코드나 원인을 만들어 내지 않습니다. wrapper·FFI·비동기 경계도 원본 실패와 문맥을 보존합니다.

제품 화면·공개 응답에는 필요한 상태·안정적인 코드·조치 안내를 제공하고 내부 상세 진단은
개발 경로에 남깁니다. 공유·로그 전에 비밀·절대 로컬 경로·계정·호스트·개인 식별자를
제거하되 코드·수치·원인 의미는 보존하고 생략·정규화를 표시합니다. 민감한 원문을 먼저
로그에 저장하거나 이 점검을 위해 비밀 파일을 읽거나 hash하지 않습니다.

정확성·상태·계약을 유지하는 복구가 있으면 작업을 계속할 수 있습니다. cache miss나
artifact 만료 후 정상 설치·재빌드는 실제 복구로 기록합니다. 경고/실패한 단계, 선택한
복구와 이유, 실제 결과와 남은 영향·미검증을 구분합니다. 정상 cache miss를 존재하지 않는
오류로 꾸미지 않습니다. 필수 검사와 최종 목표를 충족하면 복구 후 성공을 보고할 수 있습니다.
필수 실패·손상·불완전 출력·알 수 없는 계약은 명시적으로 실패합니다. `continue-on-error`,
stderr 폐기, 무조건 성공 exit로 실패를 숨기거나 자원·시간·retry 조건을 조용히 바꾸지 않습니다.

오류 경로를 변경할 때 실제 전달·안전한 복구·복구 불가 시 실패를 관련 검사로 확인합니다.
반복 경고는 횟수·영향·대표 진단을 남겨 묶을 수 있지만 단순 log level 변경으로 해결 처리하지
않습니다. 원문 전체 snapshot이나 임의의 경고 개수 검사를 자동 추가하지 않습니다.

## 검증 근거와 완료 기준

진행 공유는 완료 검증과 별도입니다. `feature/*`의 작은 부분 구현·실패 재현·수정 시도는
빌드나 테스트가 실패해도 WIP 커밋과 draft PR로 자주 공유할 수 있습니다. 전체 검사 성공을
커밋·push의 선행 조건으로 삼지 않습니다. 구현 범위·알려진 실패·실제 검사·미실행 항목과
다음 작업을 명시하고, 통합·완료 시 필요한 계약·검사·리뷰를 충족합니다. 공유 간격과
커밋 기준은 [기여 절차](../CONTRIBUTING.md#커밋-크기와-원격-공유-빈도)를 따릅니다.
PR 커밋 수 상한은 없고 장기 변경은 15~30분마다 확인해 WIP도 push합니다.
총괄은 TASK ID·계약 revision·담당 SHA/diff·실제 인수 벡터와 미실행 범위를 모아
최종 통합 검증을 수행합니다. 중간 push마다 전체 검사·학습·대국을 다시 요구하지 않습니다.

| 근거 | 보고할 범위 |
|---|---|
| 사용자 요구·채택된 설계 | 요구/결정 상태와 출처. 현재 구현·실행 결과와 구분합니다. |
| 로컬 검사 | 실제 명령·환경·기준 SHA 또는 영향 diff·입력·결과·한계입니다. |
| CI 요청 | workflow·대상 SHA·입력·run ID. 요청만으로 성공이라고 하지 않습니다. |
| 관측한 CI | 실제 job/matrix/shard 완료 상태·run/attempt·검사 범위와 실패/skip입니다. |
| 재사용한 검사 | 원본 성공과 fingerprint·현재 SHA에서 재사용 자격을 확인한 결과입니다. |
| CPU/mock 계약 검사 | 상태·인공 트리·요청 수명·I/O 확인 범위입니다. 실제 NN·GPU·arena 강도를 입증하지 않습니다. |
| 실제 NN 수치 대조 | 선택 weights·입력/policy/WDL과 독립 CPU reference의 수치·허용 오차입니다. GPU 실행과 구별합니다. |
| 실제 GPU 실행 | 같은 weights의 목표 backend·shape·batch·동기화·RAM/VRAM·deadline과 수치 대조입니다. 강도 승격이 아닙니다. |
| 모델 수치·성능 | 오차·정밀도·batch·지연·처리량·메모리 등 자체 측정입니다. |
| 대국·승격 | 확정한 동일 시간·자원·흑백 교대·통계 조건의 결과와 별도 채택 결정입니다. |

미실행·미측정·해당 없음과 이유를 명시하고 사실과 추론을 분리합니다. 학습·분석 작업의
예산 종료·취소·오류·미완료를 규칙상 terminal 결과로 꾸미지 않습니다. Arena의 엔진
불법 수·크래시·시간초과는 사전 대국 정책대로 패배에 포함하고 규칙상 종료와 구분합니다. 구현 정확성, 속도,
LC0 대비 득점률과 모델 승격은 별도 근거입니다. FLOPs·NPS·퍼즐 정확도·export 성공을
최종 대국 성능으로 표시하지 않습니다. 승격 통계·표본·예산은 [실험 계약](EXPERIMENTS.md)에서
실행 전에 잠그며 Accelerate의 기존 승률 임계값을 가져오지 않습니다.

내부 CONTROL-0(원본 W0+자체 PUCT S0)→CONTROL-1(같은 W0+새 S1)은
탐색 효과, CONTROL-1→CONTROL-2(미세조정 W1+같은 S1)는 학습 효과입니다.
TASK-D03의 runtime baseline/variant는 같은 W·S의 별도 축입니다. 외부 UCI LC0
대국은 위 내부 비교와 분리하고 조건이 다른 결과를 하나의 개선 근거로 합치지 않습니다.

문서 변경은 내용·상대 링크·책임·미결정 상태를 검토합니다. 규칙은 실제 legal/apply/result·
거절 원자성, 데이터는 상태/행동/정렬·버전, 모델은 finite/shape/mask·수치, 연동은 소유권·
오류·취소, 실행은 유한 종료·중단·복구를 확인합니다. 실제 도구가 도입되면 해당 경계의
명령과 완료 기준을 갱신합니다. 2026-10-02 초기 문서 작성 당시에는 Git·Cargo 소스·
실행 script·CI·구조 검사기가 없었습니다. 이후 공용 규약의 Git·원격 도입과 엔진 소스·
검사·CI 도입은 각각 구분하고 실제 상태를 작업 착수 때 확인합니다.
문서상 경로·검사 계약을 구현된 도구로 주장하거나
없는 검사 명령을 실행 의무로 만들지 않습니다.

## 생성물과 실행 자원

Windows 생성물 루트는 **`%APPDATA%\RoveZero`**, CI는 **`$RUNNER_TEMP/RoveZero`**입니다.
`build`, `cache`, `datasets`, `models`, `runs`, `reports`, `tmp`로 용도를 구분합니다.
소스에는 로컬 사용자 이름을 포함한 절대 경로를 하드코딩하지 않습니다. 빌드·캐시·임시는
OS·checkout·용도별 고정 슬롯을 사용하고 PID·GUID·시각만으로 무제한 누적하지 않습니다.
보존할 실험에는 ID·설정·seed·모델/규칙/인코딩 버전·출처를 남깁니다.

native ORT/CUDA 라이브러리는 RZ-D038의 제한된 예외로 checkout 사이에 공유합니다.
`native-runtime-v1/<OS>-<architecture>/` 고정 슬롯과 내용 식별자를 쓰며 실행 ID별
대용량 복제를 기본값으로 만들지 않습니다. C의 캐시는 최대 4 entry/8 GiB이고 모든
hit의 bytes·readonly pin을 검증합니다. 자동 eviction·손상 entry 교체를 하지 않으며
비정상 종료의 publication lock·미공개 staging은 소유자와 비활성을 확인한 뒤 정리합니다.
이 예외는 라이브러리 저장에 한정하며 모델·평가 cache·보존 증거에는 적용하지 않습니다.

WSL2 일반 빌드·테스트·정적 분석·환경 구성은 사용할 수 있습니다. 재생성 가능한 Linux
캐시·가상환경·중간 빌드는 `${XDG_CACHE_HOME:-$HOME/.cache}/rovezero`에 둘 수 있습니다.
보존할 모델·데이터·로그·보고서는 확인한 호스트 APPDATA를 `wslpath` 등으로 변환해
Windows 루트에 내보냅니다. 변환 실패 시 임의 경로로 대체하지 않고 OS별 바이너리·환경·
캐시를 공유하지 않습니다. 전역 `wsl --shutdown`, 다른 배포판 종료와 `.wslconfig` 수정은
일반 개발에 포함하지 않습니다.

위 Windows 내보내기는 해당 Windows 호스트의 WSL 작업에 적용합니다. 독립 Linux
클라우드는 Windows·APPDATA·`wslpath`를 요구하지 않습니다. 저장소 밖의 작업 전용
output root를 실제 환경에 맞춰 명시하고, 재생성 캐시와 보존할 산출물을 구분합니다.
작업 ID·소유자·용도·보존 기간·회수 경로를 기록하며 임시 호스트가 종료되기 전에
인수에 필요한 설정·digest·결과 근거를 합의한 보존 위치로 회수합니다. 원시 산출물을
회수하기 위해 모델·데이터·로그를 Git에 넣거나 다른 작업의 경로를 사용하지 않습니다.

장시간 학습·자가대국·대전에는 유한 game/step/time·retry 한도, CPU/GPU·memory·worker·
스레드·출력·취소와 자식 종료 방법을 기록합니다. 기존 process group·Job Object·cgroup·
container를 사용할 수 있으나 새 supervisor 설치를 일반 작업의 선행 조건으로 삼지 않습니다.
OOM 뒤 worker/batch를 조용히 줄이거나 변경 없이 무한 재시도하지 않습니다. 무거운
클라우드 실행은 승인된 비용·자원 범위와 공동 작업을 확인해 수동으로 시작합니다.
이미 사용자 배정에서 실행·자원·비용이 허용된 범위는 다시 승인받지 않고 진행합니다.
새 비용이나 배정 범위를 넘는 실행이 필요한 경우에만 구체적인 근거와 범위를 확인합니다.

정리는 승인된 소유 범위에서만 합니다. 최종 절대 경로와 link/junction 경계를 확인하고
소유한 비활성 재생성 캐시만 대상으로 삼습니다. 보존 모델·데이터·보고서·다른 checkout·
진행 작업을 일반 캐시로 삭제하지 않습니다. 이 문서가 기존 자료의 삭제 승인이 되지 않습니다.

### 빌드·테스트 생성물의 유한 수명

로컬 Clearra의 `docs/build-system.md`와 관리 코드에서 사용하는 고정 슬롯·소유 lease·
시작/종료 시 보존량 검사 원칙을 RoveZero에 적용합니다. 관리 접점은
[scripts/run_managed.py](../scripts/run_managed.py)이며, 엔진 탐색 내부와 분리합니다.
새 `scripts/` 경로는 공통 빌드·CI의 생성물 수명을 담당하며 개별 실험 복제판을 두지 않습니다.

- 일반 로컬 빌드·테스트는 `python scripts/run_managed.py -- cargo ...`로 실행합니다.
  짧은 formatting·읽기 전용 metadata 조회에는 이 접점이 필요하지 않습니다. 직접 Cargo를
  실행하면 이 정리 경로가 적용되지 않습니다. CI의 Cargo·Python 검사는 접점을 사용합니다.
- Windows는 `%APPDATA%/RoveZero/build/managed-v1`, Linux는
  `${XDG_CACHE_HOME:-$HOME/.cache}/rovezero/build/managed-v1`, CI는
  `$RUNNER_TEMP/RoveZero/build/managed-v1`를 사용합니다. 서로 다른 OS의 바이너리를 공유하지 않습니다.
- 실제 checkout 경로의 digest로 고정 슬롯을 선택합니다. SHA·시각·PID마다 새 빌드 트리를 만들지 않고,
  Cargo의 의존성 검증을 통해 재사용합니다. `CARGO_INCREMENTAL=0`과 슬롯의 `CARGO_TARGET_DIR`를
  지정하며 충돌하는 target override는 거부합니다. 임시 파일은 같은 소유 슬롯의 `tmp/`로 모읍니다.
- 기본 한도는 checkout당 **8 GiB**, 전체 관리 카탈로그 **12 GiB**, 완료 슬롯 **4개**입니다.
  시작과 정상·실패·취소 종료에서 검사합니다. 실행 중 전체 카탈로그는 5초 간격으로 관측하며,
  초과하면 소유 프로세스 트리만 중단합니다. 관측 사이의 증가가 가능한 길이 기반 한도이며
  커널 디스크 quota나 물리 할당량 측정으로 표현하지 않습니다.
- 종료 후 자식 트리의 해제가 확인되면 임시 파일을 회수합니다. 슬롯 한도를 넘은 compiler cache는
  통째로 회수하고, 전체 한도·슬롯 수를 넘으면 오래된 **완료·소유 확인** 슬롯부터 회수합니다.
  최근 실행 영수증 하나를 슬롯에 갱신하며 실패 코드와 정리 결과를 구분합니다.
- 하나의 카탈로그 owner가 재사용·회수를 직렬화합니다. 활성·중단 lease, 알 수 없거나 변경된
  소유 기록, 외부 link/junction·비밀 경로가 있으면 보존하고 실패합니다. 소유 영역 안의
  symlink는 대상을 따라가지 않고 링크만 회수합니다. 강제 종료 후 lease를 자동으로
  훔치지 않습니다. 수동 복구에는 이전 소유 트리의 종료와 정확한 경로·기록의 대조가 필요합니다.
- Windows는 실행 전 정지 상태의 자식을 Job Object에 배정하고 재개하며, Linux는 원래 leader를
  reap하기 전에 소유 process group을 종료·확인합니다. Linux의 새 session으로 이탈한 자식까지
  격리하는 sandbox는 아닙니다. 일반 명령 timeout은 1200초이며 명시 범위는 1~3600초입니다.
- 관리 cache는 배포·인수 artifact의 영구 보존 위치가 아닙니다. 나중에 사용할 엔진·입력·가중치·
  영수증·PGN은 소유 실행 안에서 정해진 보존 위치로 내보내고 식별자를 고정합니다. 기존
  등록 binary·공유 runtime·모델·보고서·다른 checkout의 legacy 트리는 자동으로 이관·삭제하지 않습니다.

### 대국 입력 복사본의 회수

Linux native arena는 결과 영수증을 저장하고 입력의 bytes·inode·hash를 다시 검증한 뒤,
소유 process group 종료와 **네 개 세션의 provider 물리 drain**이 모두 확인됐을 때
그 실행의 비실행·비JSON 개인 입력 복사본을 회수합니다. 원본 모델·가중치와 공통 runtime cache,
실행 파일·JSON 명세, PGN·로그·실행 영수증은 보존합니다. 준비 실패·불확실한 GPU 완료·
postcheck 실패에서는 일반 성공 경로로 복사본을 삭제하지 않습니다.

64 KiB로 제한한 `snapshot-retention.v1.jsonl`에 원본 artifact 식별과 회수 계획을 먼저 sync하고, 각 unlink와
완료를 기록합니다. read-only 파일 descriptor도 해제해야 공간을 회수할 수 있으므로, 삭제한
복사본의 pin을 닫고 디렉터리를 다시 read-only로 돌립니다. 기존 receipt의 `snapshots`는
실행 당시의 검증 기록이며 파일의 현재 존재를 보장하지 않습니다. 회수 journal로 현재 보존
상태를 대조하고, 재실행은 원본 artifact를 검증해 새 개인 복사본을 만듭니다.

같은 출력 루트의 기존 파일 길이와 새 실행 예약량 합계는 **32 GiB**를 넘을 수 없습니다.
깊이·entry 수·link 경계도 확인합니다. 초과하면 기존 증거를 삭제하지 않고 새 준비를 거부합니다.
같은 루트의 독립 프로세스가 동시에 쓰는 경우에는 외부 직렬화가 필요하며 이 검사는
시스템 전체 quota가 아닙니다. 승인된 유지보수로 필요한 증거를 회수한 뒤 진행합니다.

Linux 내부 파일 삭제와 Windows VHD의 물리 공간 반환은 다른 결과입니다. 테스트 종료마다
`wsl --shutdown`이나 VHD 압축을 실행하지 않습니다. 물리 공간 반환은 별도 사용자 승인 아래
사용 중인 배포판을 확인하고 오프라인에서 수행하며, 전후 실제 할당량으로 확인합니다.

## 공유 연구 기록

협업자가 재사용할 조사·비교·성능 실험·실패 분석을 선별해 `docs/research/`에 평면
Markdown으로 둡니다. 같은 연구 질문의 반복 실행은 기존 기록에 묶고 개인별·실행별
디렉터리, 단순 Git 작업마다 기록, 원시 로그 복사본을 늘리지 않습니다. 현재 전용 템플릿·
관리 도구는 없으며 아래 내용을 기존 PR 리뷰로 확인합니다.

기록에는 질문·성공 기준, 기준 commit/영향 diff, 입력·명령·seed·버전·환경·자원,
관측 결과·표본·반복 수, 해석·한계·실패/중단·후속 질문, 출처·산출물 hash·접근 참조를
남깁니다. 작성 날짜·timezone과 확인한 공개 GitHub 작성자를 기록하며 OS 계정명이나
개인 이메일로 작성자를 추정하지 않습니다. 미확인 작성자 초안은 공유 전에 확인합니다.

공유 본문·명령·발췌는 저장소 상대 경로 또는 `${ARTIFACT_ROOT}` 기준 상대 경로를
사용합니다. 절대 로컬 경로·실명·계정·호스트·이메일·장치 ID·비밀·인증 URL을 넣지
않습니다. 정규화로 옵션·seed·수치·오류 의미를 바꾸지 않으며 접근 제한·만료와 재현 한계를
밝힙니다. 이 점검을 위해 비밀 파일을 읽거나 요약·hash·보관하지 않습니다.

원시 기록·큰 산출물은 외부 생성물 루트에 보존하고 검토한 요약만 PR로 채택합니다.
공유용 정규화로 원본이나 원본 hash를 바꾸지 않습니다. 성공·실패·중단·불충분을 보존하고
자료 채택을 CI 성공·구현 완료·배포 승인·승격으로 취급하지 않습니다. 채택 문서를 캐시나
기간으로 자동 삭제하지 않습니다. 정정·통합은 기존 결론의 영향과 후속 기록을 연결해 리뷰합니다.

## 일회성 CI 수명과 보존

일회성 CI는 종료 조건이 있는 조사·실험용 임시 workflow입니다. 지속하는 학습·비교 CI를
수동 실행이라는 이유로 임시로 분류하지 않습니다. 기존 파일·입력을 먼저 재사용하고
공동작업자·checkout·브랜치·에이전트 전체에서 **같은 목표당 파일 1개, 동시 run 1개**를
유지합니다. 작성자·저장소 전체의 고정 개수 상한을 두거나 이름을 바꿔 같은 목표를 복제하지 않습니다.

생성 전 관련 PR·Actions·run 상태를 확인합니다. PR에 공개 GitHub 책임 작성자·공동작업자·
목표·경로·종료/중단 조건·실행 횟수/시간/worker/memory/artifact 예산·취소·정리 책임을
기록합니다. queued/pending/in-progress가 있으면 중복 dispatch하지 않습니다. 자기 작업과
합의한 공동 작업에만 concurrency를 적용하고 다른 목표의 run을 취소해 자리를 만들지 않습니다.
필수 병합 검사·영구 schedule로 임시 workflow를 등록하지 않습니다.

목표 완료 시 필요한 근거를 선별 보존한 후 파일 제거를 PR로 처리합니다. workflow 파일,
run·로그·artifact는 다른 정리 대상이며 파일 제거가 원격 기록 삭제를 뜻하지 않습니다.
원격 정리가 승인된 경우 일반 종료 run은 목표당 최근 **5개**를 기본 보존합니다. run ID로
세며 re-run attempt를 별도 run으로 세지 않습니다. 새 임시 artifact는 **14일** 보존을
기본으로 하되 실제 허용 한도·만료를 확인합니다. artifact 기간은 run·로그 기간과 다릅니다.

실행/대기 작업, 열린 PR의 필수 근거, 미해결 실패, 연구·모델·배포·릴리스의 원본은 개수나
기간만으로 삭제하지 않습니다. 만료·삭제 전 SHA·run/attempt·상태·결과·한계·산출물 hash·
접근 위치를 보존하고 예외 이유·재검토 조건을 남깁니다. 유일한 근거는 링크만 남겨 소실되게
하지 않습니다. 실제 삭제/보존과 소실로 인한 재현 한계를 보고합니다. 이 규약은 기존 CI
설정 일괄 변경·원격 run/로그 삭제를 승인하거나 자동 통제하는 도구가 아닙니다.

## CI 병렬화와 결과 재사용

독립 검사는 job·matrix·shard로 병렬화하고 실제 선행 산출물이 필요한 작업에만 `needs`를
둡니다. 목표당 run 1개는 내부 병렬 job을 제한하지 않습니다. 가용 runner·job 수와 각 job의
worker·스레드·CPU/GPU·memory·timeout을 함께 계산합니다. 자원 경합이 있으면 근거 있는
`max-parallel`을 둡니다. shard 입력·seed는 결정적으로 나누고 집계에서 중복·누락·실패·취소를
확인합니다. 실패 shard를 성공이나 무승부로 채우지 않으며 필요 시 `fail-fast: false`를 사용합니다.

호환되는 빌드는 한 번 생성해 artifact로 전달합니다. OS·아키텍처·target·toolchain/ABI·
옵션·정밀도·source/의존/생성 입력 fingerprint, 생산 repository/workflow/run/attempt/SHA와
파일 digest를 확인합니다. 이름이 같거나 digest만 일치한다고 출처·입력 호환성을 가정하지 않습니다.
확인할 수 없거나 불일치하면 재빌드 또는 명시적 실패로 처리합니다.

성공한 검사도 결과에 영향을 주는 코드·의존성·fixture·계약·옵션·seed·환경과 검사 범위가
같으면 다른 SHA에서 재사용할 수 있습니다. 입력 집합의 간접 의존과 실제 tool/환경 버전도
포함합니다. 관련 없는 문구·작성 시각 때문에 모든 검사를 반복하지 않습니다. 반대로 현재
문서·index·외부 상태 등 새 입력을 요구하는 검사는 확인합니다. 불완전한 입력 집합·만료된
근거·미확인 성공은 재사용하지 않고 해당 검사를 실행합니다.

현재 SHA의 확인 결과에 원본 SHA·run/attempt·검사 범위·성공 상태·fingerprint·재사용 여부를
남깁니다. 필수 check가 있다면 현재 대상의 확인 job이 근거를 검증합니다. 이전 실제 실행을
현재 SHA의 직접 실행으로 표시하지 않습니다. 실패·중단·skip·`continue-on-error`로 가린
필수 실패를 성공 근거로 쓰지 않습니다. 대국 독립 재실행·배포·승격 승인은 별도 조건입니다.

cache는 재생성 가능한 가속 수단입니다. key에 용도·OS·도구·관련 입력 fingerprint를
반영하며 miss·만료·불일치 시 정상 설치·빌드를 수행합니다. cache hit 자체는 검사 성공이
아닙니다. 비밀·credential·보존 모델·데이터·보고서를 cache에 넣지 않습니다. 신뢰하지 않는
PR의 artifact·cache를 높은 권한의 실행·배포에 검증 없이 사용하지 않습니다.

실제 CI 변경 후에는 병렬 집계·artifact 소비·재사용 확인·영향 검사 재실행과 cache miss·
만료·불일치·실패 경로를 검증합니다. warm cache 결과를 clean build로 표시하지 않습니다.
시간·재사용·미검증 범위는 관측 결과로 보고하고 존재하지 않는 CI의 성능 개선을 주장하지 않습니다.

## 소스 접근과 구조 검토

비밀 파일은 읽거나 요약·검색·수정·출력하지 않습니다: `.env`, `.env.*`, service account
JSON 파일, SSH key, API key, credential 파일. 명시적 요청 없이 `node_modules/`, `dist/`,
`dist-server/`, `build/`, `coverage/`, `models/`, `checkpoints/`, `.cache/`를 조사하지 않습니다.
`package-lock.json`은 의존성 변경이 명시적으로 요청된 경우에만 조사합니다. Git 도입 후
Git 추적 소스를 우선하며 비밀을 검사 목적으로 열거나 hash하지 않습니다.

새 최상위 경로·생성물 예외는 정확한 경로·책임·이유·검토 범위를 설명합니다. 10 MiB를
초과하는 추적 파일은 이유와 보완 검토가 필요하며 이 크기는 SRP 기준이 아닙니다.
`docs/reference/`의 두 핸드오프 원문은 허용한 출처 snapshot입니다. 원시 로그·모델·
운영 데이터셋을 source로 등록하거나 광범위 예외로 포함하지 않습니다. 초기 공용 규약
도입 단계에는 구조 정책·검사 script·workflow가 없습니다. 실제 상태를 확인하고
확정한 Rust 책임 경로에 소스를 도입할 때
toolchain·feature·명령·검사 범위를 리뷰하고, Git index 메타데이터 검사를 전체 코드
품질·파일 내용 보안의 증명으로 취급하지 않습니다.
