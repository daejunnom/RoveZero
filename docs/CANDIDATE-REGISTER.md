# 후보 작업카드 등록부

이 문서는 [RoveZero v0.2.0 핸드오프](reference/RoveZero_Handoff_v0.2.0_KO.md)의 5~9장·16장에 있는 **76개 후보**를 누락 없이 구현 작업 단위로 옮긴다. A01~E12의 46개 원문 제목과 출처는 [PlyZero v0.1.0](reference/PlyZero_Handoff_v0.1.0_KO.md)의 이력을 잇고, F01~F30의 30개가 v0.2.0에서 추가되었다. 연구 분류·측정 원칙은 v0.2.0 14~17장을 적용하며 실제 착수 순서는 현재 사용자의 20개 TASK 지시를 우선한다. 현재 모든 카드는 문서 등록 상태이며 구현·실험은 미착수, 성능은 미측정이다.

현재 사용자 결정은 독립 Rust 원본 구현과 자체 작성 코드의 MIT 라이선스 방향, 기존 가중치를 읽는 최소 PUCT 엔진을 먼저 만드는 것이다. LC0 fork·소스 결합을 기본값으로 채택하지 않는다. 기존 가중치의 실제 형식·출처·권리·backend는 선택 후 호환 검증해야 한다. 자체 코드 MIT와 외부 코드·가중치·데이터의 라이선스는 별개다. 최소 공통 계약의 소유자는 이 작업의 총괄이며 CARD-A01 등 연구 후보의 A 분류와 담당 작업 A의 소유권은 별개다.

현재 구현·평가의 잠근 순서는 **CONTROL-0: 기존 가중치+baseline PUCT → CONTROL-1: 동일 가중치+새 search → CONTROL-2: 동일 CONTROL-1 search+미세조정 가중치 → TASK-F03: architecture 하나**다. baseline/새 search는 TASK-B02의 기준·variant이며 실제 가중치 연결은 TASK-C02/C03 뒤 이루어진다. TASK-F01은 학습 데이터 계약·누출 검사, TASK-F02는 미세조정이다. TASK-D03은 같은 가중치·같은 search에서 계측으로 고른 runtime 개선 한 가지를 비교하는 독립 축이다. 연구 후보의 R0~R7은 원문 단계 연결을 보존한 설명이며 이 확정 작업 순서나 [구현 지시서](IMPLEMENTATION-DIRECTIVES.md)의 의존관계를 앞당기지 않는다. 특히 architecture 후보는 TASK-F02 검증 뒤 TASK-F03에서 하나를 고른다. 76개 전체는 후속 연구 등록부이며 현재 20개 담당 작업 전체의 구현 범위가 아니다.

각 카드의 **원문 분류·하드웨어 등급·출처 번호는 핸드오프의 귀속을 보존**한다. 이 문서는 외부 논문·라이선스·릴리스·가변 웹 자료를 새로 검증한 보고가 아니다. R01~R93의 원문 링크와 확인일·주석은 v0.2.0 18장을 읽는다. 해당 원문의 기법 존재·저자 성능 보고와 RoveZero에 대한 적용 가설을 구분한다. 등급의 높음·조건부·낮음은 전부 설계 추론이며, 구현 채택·GPU 속도·Elo·현재 실행 권한을 뜻하지 않는다.

**작업 배치 제안, 전제·최소 작업, 검증·기각 기준은 이번 구현 지시서에서 구체화한 조건**이다. 원문에 명시된 범위를 넘는 수치 임계값·모델·스택은 채택하지 않았다. 실행을 시작할 때 담당자·변경 범위·실제 명령·유한 예산·수치 허용오차·통계 기준을 [DECISIONS](DECISIONS.md)와 실험 manifest에 잠근다. [ARCHITECTURE](ARCHITECTURE.md), [EXPERIMENTS](EXPERIMENTS.md), [ENGINEERING-STANDARDS](ENGINEERING-STANDARDS.md)의 계약을 함께 따른다.

## 등록부를 사용하는 순서

1. 해당 비교의 identity·정확성·manifest와 R1 계측 근거를 먼저 확인한다. 자체 엔진 연구에는 C02/C03 기준과 D02 계측을 사용하며 외부 LC0 대국 비교에는 해당 R0 runner·pair 계약을 추가 요구한다. 자체 계측·runtime 연구 전체가 외부 LC0 대국 완료를 기다리는 것은 아니다. 카드 수를 구현 수로 해석하거나 76개를 동시에 구현하지 않는다.
2. 관측한 병목·실패군과 사용자 결정에 맞는 카드 하나를 고른다. 같은 파일에 다른 후보를 함께 넣더라도 실험의 변경 변수는 하나로 유지한다.
3. 기존 가중치와 입력·출력을 유지하는 실행 경로와 새 입력·본체·head·학습을 요구하는 모델 경로를 분리한다. 새 표현·잠재 구조를 기존 가중치의 단순 토크나이저 교체로 표시하지 않는다.
4. 작업카드의 전제, 독립 비교군, E/A/S, G/H/C/O, 수명·취소·시간 계약을 manifest에 기록한다. 카드의 단계 연결은 위치 제안이며 통과 사실이 아니다.
5. 작은 진척은 기존 WIP 커밋·push 규약으로 공유한다. 검증되지 않은 카드 상태·성능을 완료로 보고하지 않는다.
6. 통과한 단독 요소만 R7에서 결합하고 각 요소 제거 실험을 수행한다. 실패·보류·기각·불확정 카드도 ID·출처와 근거를 남긴다.

| 분류 | 구현자가 지킬 경계 |
|---|---|
| E — 의미 보존 | 독립 참조 경로와 출력·상태·수명 계약을 비교한다. 실행 순서가 평가 선택이나 결과를 바꾸면 S/A를 추가한다. E 불일치를 평균오차로 감추지 않는다. |
| A — 모델·근사 변경 | 입력·가중치·출력·정밀도·budget·fresh/warm provenance를 바꾼 별도 artifact로 식별한다. 품질·tail error·calibration·같은 시간 대국을 측정한다. |
| S — 탐색·스케줄 변경 | 고정 evaluator에서 실제 소비 평가·중복·취소·deadline·선택 편향을 측정한다. 모델 품질 개선과 분리한다. |
| G — GPU 중심 | 기존 LC0 실행 개선과 GPU 친화 새 모델을 구분한다. CPU 준비·전송·큐·backup도 전체 비용에 포함한다. |
| H — CPU 보조 | helper·history·gate·cache 관리 비용과 CPU/RAM을 공통 자원 상한 안에 포함한다. GPU 직접 가속 주장과 구분한다. |
| C — CPU 비교 | CPU 모델·선택 탐색의 독립 비교군이다. 결과를 G 아키텍처 검증으로 승계하지 않는다. |
| O — 오프라인 | 데이터·학습·튜닝·분석·실험 관리다. 개발·훈련의 GPU 적합성을 온라인 추론 점수로 옮기지 않는다. |

## 공통 진입·검증·중단 조건

각 카드에서 쓰는 `R0/R1`은 비교 가능한 기준 identity·정확성·전체 계측의 선행
근거를 뜻한다. 원문의 외부 LC0 gate는 보존하되 자체 내부 A/B에는 해당 RoveZero
기준을 적용한다. LC0 강도를 주장할 때는 외부 runner·pair·통계 인수가 별도로 필요하다.

A~F의 클라우드 개발에는 GPU가 없을 수 있다. 계약·코드·fixture·CPU/mock와
가능한 CPU 신경망 참조를 먼저 검증하고 목표 RTX 4050 6GB의 실제 GPU 측정·
정식 대국·학습 인수는 총괄 I02가 지원 환경에서 별도로 확인한다. D02 CPU/mock
지연과 D03의 실제 GPU 개선을 구분한다. CUDA capability 부재·GPU 검사 skip·
미실행을 기록하며 조용한 CPU 대체나 GPU gate 통과로 표시하지 않는다. 개발 환경의
GPU 유무로 아래 76개 후보의 원문 하드웨어 등급·출처를 변경하지 않는다.

모든 런타임 카드는 비교용 LC0 commit·가중치 hash·backend·정상 최적화 옵션·장비 상한과 자체 엔진의 baseline artifact를 함께 식별한다. 기존 가중치 경로는 선택한 형식의 입력·head·history 의미를 검증한 호환 실행이며 소스 fork를 뜻하지 않는다. R2의 실행 변경은 입력·head·학습을 함께 변경하지 않는다. TASK-F03에서 선택할 새 architecture A 카드의 최소 비교군은 같은 데이터·출력 계약·학습 비용의 소형 square-token 모델이며 강한 외부 LC0 기준선도 별도로 유지한다. 자체 모델 개선과 LC0 대비 개선을 분리한다.

모든 카드의 E/A/S 실험에서 cold/fresh, parent→child, sibling, transposition, eviction, 긴 trace와 가능한 batch 크기를 나눈다. batch 1/4/16/64/256은 원문의 시작 후보이며 실제 장비 한도와 search 분포를 확인한다. P50/P95/P99 응답, queue·전송·GPU 완료·backup, 실소비 고유 평가, 미사용·취소·중복, RAM/VRAM, 모델·cache 상주량을 보고한다. 개별 커널 합계와 pipeline critical path·처리량을 구분한다.

같은 완전 시작 상태에서 두 엔진의 흑백 배정을 교환하고 동일한 clock·increment·전체 자원 상한에서 판정한다. 자기 시간 밖 helper·speculation, 최종 세트 튜닝, 실패 판 삭제, 자동 온라인 가중치 변경은 허용하지 않는다. 게임 내 history/correction은 명시 옵션·자기 시간·새 게임 reset·raw cache 분리 조건을 만족한다.

규칙 손실, 합법 수·WDL 관점 불일치, 모델/history/정밀도/cache 혼입, 늦은 결과의 새 root 반영, 취소 후 중복 backup, 시간·자원 조건 위반은 해당 실행 해석을 중단할 조건이다. E가 수치 허용오차를 넘으면 의미 보존 주장을 중단한다. A/S가 미리 정한 실패군·시간·메모리·강도 기준을 만족하지 못하면 해당 구성은 보류 또는 기각하며, 측정 범위 밖의 다른 배치·장비까지 일반화하지 않는다. 예산 끝의 불확정은 기각과 구분한다.

카드 결과는 ID, 원문 출처, 담당자, 설계 결정, 변경 SHA·artifact hash, track, 변경 유형, 비교군, manifest, 실행 검사와 미실행 항목, 부정적·불확정 결과, 보류/기각 이유, 다시 검토할 조건으로 보존한다. 원시 산출물은 저장소 밖에 두고 검토된 작은 요약과 논리 경로만 공유한다.

## ID 구분과 현재 상태

이 등록부의 제목은 **CARD-A01~CARD-F30**이며 각 카드의 원문 후보 ID A01~F30을 보존한다. 구현 지시서의 **TASK-A01~TASK-F03** 등의 담당 작업 ID와는 다른 namespace다. 예를 들어 CARD-C02는 recurrent evaluator 연구이고 TASK-C02는 담당 작업의 번호다. 카드의 A/B/C/D/E/F 문자로 현재 담당자를 추정하지 않는다. 카드 적용은 실제 TASK와 변경 manifest에 따로 연결한다.

상태는 등록 → 설계 선택 → 구현 중/WIP → 계약 검증 → 독립 측정 → 단독 판정 → R7 결합 판정으로 기록한다. 보류·기각·불확정은 ID를 유지하는 분기 상태이며 다음 상태로 자동 승격하지 않는다. 현재 등록부에는 실험 실행·통과·기각 결과가 없다.

## A — 입력 표현·모델 본체 (7개)

공통 gate: 정확 보드·전역 상태와 합법 수 출력은 Rules/State와 인코딩 계약이 소유한다. 표현·관계·본체를 각각 독립 변경한다. A01을 이미 존재하는 GAB/smolgen/RPE를 뺀 약한 LC0와 비교하지 않는다. 모든 새 표현은 학습과 export 호환성·추론 비용 검증이 필요하다.

### CARD-A01 — 64칸 토큰 + 상대 위치·체스 관계

**작업 배치 제안:** R3 / G·O / A / **현재 상태:** 등록·미착수·미측정

**원문 분류 보존:** **근거:** 체스 근거 / **순서:** 우선: 기준선 / **변경:** A
